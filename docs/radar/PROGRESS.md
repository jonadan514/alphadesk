  라이브 갱신, 나머지는 캐시 사용. **이 단계에서 `run_watchlist_screen.py`가

**명세와 다르게 구현한 것**
- `fetch_status`에 SPEC 원안에 없는 `info_payload` 컬럼을 추가함. 트랩 필터의
  `regime_fit` 판정·시가총액 필터·중국기업 판별이 재무제표가 아니라 yfinance
  `.info` 스냅샷에 의존하는데, 이걸 캐시하지 않으면 재무제표를 캐시해도 종목당
  `.info` 라이브 호출이 매주 그대로 남아 호출량 감소 목표(10분의 1)를 절반만
  달성하게 되는 문제를 코드 조사로 발견 — 대화로 상의 후 추가하기로 결정.
- `rate_limited` 상태 구분을 이번 단계에서 구현하지 않음 — 실패는 전부
  `no_data`로 기록하는 의도적 단순화. §6(실패 내성)에서 지수 백오프 재시도와
  함께 제대로 구분할 예정.
- 종목 단위 `try/except`를 백필 스크립트에 추가함 — 명세에 명시되진 않았지만,
  셀프 리뷰 중 저장 경로(JSON 직렬화 등)에서 예외가 나면 배치 전체가 죽어서
  §5가 말하는 "중간에 실패해도 앞서 받은 건 남는다"가 저장 경로에는 적용 안
  되는 구멍을 발견해 추가함.
