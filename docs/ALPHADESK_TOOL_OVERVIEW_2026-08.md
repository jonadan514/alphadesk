# AlphaDesk 툴 구성 개요 (2026-08 기준)

이 문서는 AlphaDesk의 현재 구조·설계 결정·자동화 흐름을 한 번에 파악할 수 있도록
정리한 자료입니다. 다른 대화(예: 새 Claude 세션)에서 이 툴에 대해 이야기할 때
컨텍스트로 붙여넣는 용도로 씁니다.

---

## 1. 이 툴이 뭔가

**AlphaDesk** — 미국(S&P 500)·한국(KOSPI/KOSDAQ) 주식을 대상으로 한 개인 투자자용
분석 대시보드. 저장소: `jonadan514/alphadesk`, 배포: Vercel
(`alphadesk-eta.vercel.app`).

**사용자(제작자 본인)의 실제 투자 스타일**: 단기 스윙이 아니라 **1~3년 펀더멘털
보유**. 이 사실이 2026-08 세션에서 명확해지면서 툴 전체 구조가 크게 바뀌었다
(§7 참고).

## 2. 핵심 설계 철학

> "무엇을 사라고 순위 매겨 알려주는 도구"가 아니라
> "재무적으로 문제없는 후보를 순위 없이 보여주고, 최종 판단은 사람이 하는 도구"

- **랭킹 없음**: 예전엔 재무 필터 통과 종목을 모멘텀·품질 점수로 다시 줄 세워
  시장별 상위 50개만 보여줬다. 지금은 그 점수 체계를 완전히 제거했다 —
  필터를 통과한 종목은 **전부** 순위 없이 후보가 된다.
- **재무 필터는 방어용**: "뭘 사라"가 아니라 "뭘 사지 마라"만 판단한다.
- **시장 타이밍은 참고용, 장기 매수는 게이트와 무관**: 마켓 게이트/체제 판정은
  여전히 계산하지만, 1~3년 보유 포트폴리오의 매수는 게이트가 STOP이어도
  차단하지 않는다 (저평가 우량주를 시장이 안 좋을 때 사는 것도 장기 투자에선
  정당한 진입이라는 판단).
- **장기 보유엔 자동 손절 없음**: 1y/3y 포트폴리오는 가격 기반 자동 매도가
  없다. 재무 훼손·큰 폭 하락을 감지하면 **알림만** 남기고, 매도 여부는 항상
  사용자가 직접 판단한다.
- **자동화는 주 1회**: 예전엔 하루 2회 + 주 1회였는데, 종목별 AI 논지 생성이
  없어지고 나니 그렇게 자주 돌 이유가 없어져서 주 1회로 통일했다.

## 3. 데이터 흐름 개요

```
[GitHub Actions, 주 1회 자동 실행]
        │
        ├─ Weekly Watchlist Screen (일요일 22:00 UTC)
        │    유니버스 수집 → 재무 필터(트랩 필터) → watchlist_candidates 테이블
        │    (순위 없이 통과 종목 전부) + watchlist_candidate_history(영구 보존)
        │    └─ Watchlist Narratives: 종목별 뉴스 → GPT 요약 → narrative_briefs
        │    └─ Weekly Briefing: 주간 총평 문서 생성 + 텔레그램 발송
        │
        ├─ Weekly Market Analysis (월요일 22:00 UTC, 스크리닝 다음날)
        │    체제·게이트·지수예측·섹터분석 갱신
        │    → watchlist_candidates 기준으로 장기 포트폴리오(1y/3y) 매수 실행
        │    → 텔레그램 요약 발송
        │
        └─ Performance Tracking (일요일 23:00 UTC)
             과거 후보들의 30/60/90/180/365/730일 후 실제 수익률 계산 (성적표)
        │
        ▼
   Turso (libSQL) — 단일 데이터 저장소
        │
        ▼
   Next.js 프론트엔드 (Vercel) — API 라우트가 Turso를 직접 읽음
```

## 4. 재무 필터 (트랩 필터) — 지금 기준

**목표**: "명백히 위험한 것만 제외"가 아니라 **"확실히 우량한 것만 통과"**.
(2026-08-21: 필터가 너무 느슨해서 570종목 중 302개(53%)가 통과하는 문제가
있어 기준을 상향 조정했다.)

| 항목 | 탈락 기준 |
|---|---|
| Piotroski F-Score | 6점 미만 (9개 항목 중 6개 미만 충족) |
| 이자보상배율 (EBIT/이자비용) | 3배 미만 |
| 부채비율 (총부채/자기자본) | 150% 초과 (금융업 제외) |
| 영업현금흐름 | 최근 2년 연속 마이너스 |
| 매출 + 순이익 | 3년 연속 동시 감소 (매출만 2년 연속 감소도 별도 감점) |
| ROE | 12% 미만 |

**Piotroski F-Score 9개 항목** (재무제표 3개년 비교, 각 1점):
수익성(ROA 양수·CFO 양수·ROA 개선·CFO>ROA) 4개, 재무구조(레버리지 감소·유동성
개선·희석 없음) 3개, 운영효율(매출총이익률 개선·자산회전율 개선) 2개.

**결과 (2026-08-21 기준 실행)**: 유니버스 573종목 → 통과 161종목 (28%,
미국 149 + 한국 12). 기준 상향 전엔 302종목(53%)이 통과했었다.

구현: `src/analyzers/trap_filter.py`

## 5. 유니버스 수집

### 미국
S&P 500 (시가총액 $2B+). Wikipedia 목록 또는 캐시된 CSV 사용.

### 한국 — 결론: 정적 리스트로 확정 (전체 수집은 보류)
- **정적 KOSPI 대형주 리스트 87종목**을 계속 쓴다. 전체 KOSPI+KOSDAQ 자동
  수집을 두 가지 방법으로 시도했으나 **둘 다 GitHub Actions에서 막혀서
  2026-08-27에 보류 결정**:
  1. pykrx (data.krx.co.kr 직접 스크래핑) — 2026-07~08월 4주 연속 실패
     (pykrx GitHub 이슈 #170 "IP 차단", #151 등 동일 문제 다수 보고됨).
  2. 공공데이터포털 "금융위원회_KRX상장종목정보" API (무료·자동승인 공식
     API라 지역 차단이 없을 거라 기대했음) — 실제로는 `apis.data.go.kr`로
     TCP 연결 자체가 30초 타임아웃(`ConnectTimeoutError`) 남. pykrx와 같은
     근본 원인(GitHub Actions의 해외 IP를 한국 사이트가 차단)으로 추정.
- 두 함수(`_kr_universe_public_api`, `_kr_universe_pykrx`) 코드는 fallback
  체인에 그대로 남겨뒀다 — 로컬/한국 리전 환경에서 실행하면 될 가능성이 있고,
  나중에 한국 리전 프록시/서버를 두면 재활용할 수 있어서다. 근본 해결은
  한국 리전 IP 확보(자체 서버/프록시)뿐이며, 비용·유지보수 부담 때문에
  일단 보류하기로 함.
- 예전엔 "KRX_ID/KRX_PW를 GitHub secrets에 등록하면 된다"는 안내가 코드에
  있었는데, 실제로는 그 값을 어디서도 읽지 않는 **틀린 안내**였다 (확인 후
  정정).

구현: `src/collectors/watchlist_collector.py`

## 6. 장기 포트폴리오 (페이퍼 트레이딩 시뮬레이션)

4개 포트폴리오만 운용 (예전엔 스윙 단기/중기/120일 6개가 더 있었으나 제거):

| ID | 배분 방식 | 보유기간 |
|---|---|---|
| `equal_1y` | 균등 배분 | 1년 |
| `equal_3y` | 균등 배분 | 3년 |
| `weighted_1y` | Piotroski 점수 가중 | 1년 |
| `weighted_3y` | Piotroski 점수 가중 | 3년 |

- 가중 배분: Piotroski 7~9점 → 가중치 2.0, 5~6점 → 1.0, 그 외 → 0.5
  (예전엔 스크리너 등급 A/B/C 기반이었으나 스크리너 제거로 대체)
- 전부 `alert_only=True` — 자동 손절/익절 없음, 보유기간 만료(1년/3년)만
  자동 매도로 시뮬레이션 마감
- 매수 소스: 그 주 `watchlist_candidates` (게이트와 무관하게 매수)

구현: `src/portfolio/tracker.py`

## 7. 최근 대규모 변경 (2026-08 세션)

**계기**: 대화 중 사용자가 "나는 스윙보다 1~3년 펀더멘털 투자 스타일"이라고
밝히면서, 기존 툴(모멘텀 스크리너 기반)이 실제 투자 스타일과 안 맞는다는 게
드러남.

**제거된 것**:
- 미국 6팩터·한국 4팩터 복합 점수 스크리너 (등급 A~F, BUY/WATCH/HOLD 액션)
- 시장 적합 점수(품질40+모멘텀35+체제25)로 상위 50종목만 추리던 랭킹
- 종목별 AI 투자논지(thesis)·목표주가 자동 생성 (일간 파이프라인에서)
- 스윙 페이퍼 포트폴리오 6개 (단기/중기/120일 × 균등/가중)
- `/top-picks` 페이지 전체

**새로 생기거나 유지된 것**:
- 재무 필터(트랩 필터) 통과 종목 순위 없이 리스트업 → `/watchlist`가 메인 허브
- 뉴스 기반 네러티브 브리프(스토리·촉매·리스크·시장 단기 관심도) — 장기 투자
  프레이밍으로 프롬프트 재작성, 여전히 유지·강화됨
- 장기(1y/3y) 알림 전용 포트폴리오
- 매수체크(`/workflow`): BUY·등급·점수 조건 → 워치리스트 포함(재무 필터
  통과)·Piotroski≥6·네러티브 브리프 확인으로 교체

**자동화 주기**: 하루 2회 + 주 1회 → **주 1회**로 통일
(`daily-analysis.yml` → `weekly-analysis.yml`로 이름도 변경)

## 9. 프론트엔드 페이지 (Next.js App Router)

| 경로 | 역할 |
|---|---|
| `/` | 종합 판단(게이트) + 체제 점수 + 이번 주 워치리스트 후보 수 |
| `/watchlist` | **메인 허브** — 재무 필터 통과 후보(순위 없음) + 내 관심종목 + 네러티브 브리프 + 정성 체크리스트 |
| `/workflow` | 매수 체크 — 워치리스트 포함·Piotroski·네러티브 등 자동 판정 + 포지션 사이징 계산기 |
| `/portfolio` | 실거래 기록 CRUD + 벤치마크 대비 성과 |
| `/risk` | 시뮬레이션 포트폴리오(`equal_1y` 기준) 리스크 분석 |
| `/regime` | 시장 체제(risk_on/neutral/risk_off/crisis) 판정 근거 |
| `/sector` | 섹터별 상대강도·경기 사이클 |
| `/briefing` | 주간 브리핑 (읽는 문서 형태) |
| `/guide`, `/guide/detail` | 사용 설명서 |

DB: Turso(libSQL), 프론트는 읽기 전용 API 라우트로 직접 접근.

## 11. 기술 스택 요약

- **프론트엔드**: Next.js 15 (App Router), TypeScript, Vercel 배포, Turso 직접 조회
- **백엔드**: Python (GitHub Actions 크론), yfinance/pykrx/공공데이터포털 API로 수집,
  GPT-4o mini로 뉴스 요약, Turso HTTP API로 저장
- **DB**: Turso (libSQL) — 단일 소스, 프론트/백엔드 공용
- **알림**: 텔레그램 봇 (주간 요약, 실패 알림, 손절/재무훼손 알림)
