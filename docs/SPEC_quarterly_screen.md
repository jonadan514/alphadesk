# 분기 리서치 화면 설계 (REDESIGN_SPEC 8장 구현 지시서)

작성 2026-09-23. REDESIGN_SPEC.md 8장은 네 줄짜리 요구사항이라, 그대로 코드로 옮기기엔
정해야 할 게 많이 남아 있다. 이 문서가 그 빈칸을 채운다 - **구현자가 다시 판단하지 않아도
되도록** 섹션 구성·정렬·문구·빈 값 처리까지 정한다. 색·간격 같은 시각 요소는 기존
`app/radar/page.tsx`의 토큰과 관례를 그대로 쓴다(새로 만들지 않는다).

---

## 0. 이 화면의 편집 방침

주간 화면(`/radar`)은 "얼마나 이른 신호인가"의 3단계(Quiet → Buzz → Full)를 섹션으로
드러낸다. 분기 화면은 구조가 다르다. **재무와 뉴스 두 축의 2×2이고, 축이 서로 독립이다.**

그래서 이 화면의 편집 방침은 한 줄로 이렇다.

> **두 축이 어긋나는 자리가 가장 쓸모 있다.**

- `조용한 변화`(재무 O, 뉴스 X) - 실적이 먼저 움직였는데 시장이 아직 모른다. **이 도구가 있는 이유.**
- `기대 선행`(재무 X, 뉴스 O) - 기대가 먼저 붙었다. 다음 분기에 재무가 따라오는지가 관전 포인트.
- `확인된 변화`(재무 O, 뉴스 O) - 둘 다 맞았지만 남들도 안다. 밸류를 꼭 본다.
- `관심 밖`(재무 X, 뉴스 X) - 이번 분기엔 볼 이유가 없다.

주간 화면과 같은 원칙: **순위를 만들지 않는다.** 섹션 순서는 편집 방침이지 점수가 아니고,
섹션 안의 정렬도 "보는 순서"일 뿐이다(아래 2-3).

## 2. 테마 목록 화면

### 2-1. 맨 위: 기준 정보 한 줄

SPEC 8장이 "모든 화면에 데이터 기준 분기와 시장 매출 증가율 중앙값을 표시"하라고 했다.

```
기준 분기 2026Q3 · 한국 시장 · 유니버스 매출 증가율 중앙값 16.0% (표본 607개)
```

- 중앙값은 **참고값이고 판정에 쓰지 않는다**는 걸 한 번은 적는다(툴팁이나 작은 글씨).
- 중앙값이 없으면(`median_revenue_growth` NULL) `중앙값 계산불가`로 쓴다. 숨기지 않는다.

### 2-2. 그 아래: 2×2 요약 (이게 분류 필터다)

SPEC 8장의 "분류별 필터"를 별도 드롭다운으로 만들지 않는다. **2×2 자체를 누르는 필터로
만든다** - 구조가 보이면서 필터도 된다.

```
                뉴스 적음          뉴스 많음
  재무 켜짐   [조용한 변화 16]   [확인된 변화 6]
  재무 꺼짐   [관심 밖 6]        [기대 선행 1]

              데이터부족 3
```

- 각 칸: 분류 이름 + 개수. 누르면 아래 목록이 그 분류만 남는다(다시 누르면 해제).
- **칸 크기는 개수와 무관하게 동일하게 둔다.** 개수로 칸을 키우면 "많은 게 중요한 것"으로
  읽히는데, 실제로는 반대다(조용한 변화가 16개인 건 기준값이 아직 헐거울 수 있다는 뜻이지
  16개가 다 좋다는 뜻이 아니다).
- 강조는 `조용한 변화` 칸에만 준다(주간 화면에서 `Quiet Strength`만 채운 색을 쓴 것과 같은
  이유 - 이 도구의 존재 이유이므로).
- 데이터부족은 2×2 **밖에** 따로 둔다. 4칸 중 하나가 아니다.

### 2-3. 그 아래: 분류별 섹션과 테마 목록

섹션 순서(고정): **조용한 변화 → 확인된 변화 → 기대 선행 → 관심 밖 → 데이터부족**

각 섹션은 이름 + 한 줄 설명을 단다. 설명 문구는 위 0장의 것을 그대로 쓴다.

**섹션 안의 정렬: 변화 기업 비율 내림차순.**
`조용한 변화`에 16개가 들어가는 게 실측이라(2026Q3 한국), 순서가 없으면 어디부터 볼지
알 수 없다. 이 비율은 그 테마를 그 칸에 넣은 바로 그 값이라 새 점수를 만드는 게 아니다.
비율이 같으면 변화 기업 수가 많은 쪽, 그다음 테마 id 순.

**테마 한 줄에 들어가는 것** (SPEC 8장 목록 그대로):

| 항목 | 값 | 없을 때 |
|---|---|---|
| 테마 이름 | `themeName(id).ko` | - |
| 분류 배지 | 4칸 이름 | 데이터부족 섹션에선 생략 |
| 변화 기업 | `7/8 (88%)` - 변화 기업 수 / 판정 가능 기업 수 | `판정 가능 기업 부족 (1곳)` |
| 뉴스 비율 | `1.99배` | `-` |
| 지난 분기 | 지난 분기 분류 이름, 달라졌으면 `관심 밖 → 조용한 변화`처럼 화살표로 | `지난 분기 기록 없음` (첫 실행이면 전부 이 상태다 - 정상) |

- 테마 줄을 누르면 아래에 소속 기업 카드가 펼쳐진다(주간 화면의 기업 목록과 같은 동작).
- **판정 가능 기업 수를 반드시 같이 보여준다.** `7/8`과 `7/30`은 전혀 다른 근거인데
  비율만 보면 구분이 안 된다.

### 2-4. 데이터부족 섹션

4칸에 못 들어간 테마는 **왜 못 들어갔는지**를 적는다. 실측(2026Q3)에서 한국 3개는 전부
"뉴스만 없음"이고 미국 9개는 재무·뉴스가 섞여 있다 - 대처가 다르므로 구분이 정보다.

| 상태 | 표시 |
|---|---|
| 재무만 판정됨 | `뉴스 이력 부족` + 재무 값은 그대로 보여준다 |
| 뉴스만 판정됨 | `판정 가능 기업 부족 (N곳)` + 뉴스 비율은 그대로 |
| 둘 다 없음 | `재무·뉴스 둘 다 부족` |

- 이 섹션은 기본 접어두되, 개수는 항상 보이게 한다. 숨기면 "화면에 안 나오는 테마"가
  생긴 걸 모른다.

## 3. 소속 기업 카드 (테마 상세)

SPEC 5장의 기업 카드 = 변화 신호 3개 + 변화 기업 판정 + 트랩 필터 + 밸류 위치.

### 3-1. 표 구성

기존 주간 화면의 기업 표와 같은 모양(가로 스크롤 허용)을 쓰되 칼럼이 다르다.

| 칼럼 | 내용 | 비고 |
|---|---|---|
| 종목 | KR은 `krStockName()` + 코드 작게, US는 티커 | 기존 관례 그대로 |
| 변화 신호 | `매출전환 / 매출흐름 / 이익전환` 3칩, 각각 O·X·– | –는 데이터부족(탈락 아님) |
| 변화 기업 | O / X / – 배지 | 이 표의 주인공이라 다른 칩보다 강조 |
| 매출 | `1,715 → 2,740억` 형태로 1년 전 → 최근 | 둘 중 하나라도 없으면 `-` |
| 밸류 | `PSR 3.39` + 등급 배지(싼 편/중간/비싼 편) | 등급 없으면 배지 생략 |
| PER | 수치만 | 적자면 `-` (계산 실패가 아니라 원래 안 보여주는 것) |
| 재무 | 기존 트랩 필터 배지 그대로 재사용 | SPEC 5-3 "옆에 표시, 판정에 섞지 않는다" |

### 3-2. 필터 (SPEC 8장 "필터 예")

표 위에 토글 세 개. 기본은 전부 꺼짐(전체 보기).

- `변화 기업만` → `changed = true`
- `재무 통과만` → 트랩 필터 `status = pass`
- `밸류 싼 편만` → `valuation_tier = 싼 편`

### 3-3. 정렬

기본: 변화 기업(O 먼저) → PSR 낮은 순. 사용자가 바꾸는 UI는 v1에서 만들지 않는다.

### 3-4. 빈 값 규칙 (원칙 4)

**`–`(데이터부족)와 `X`(탈락)를 절대 같은 모양으로 그리지 않는다.** 색도 다르게 한다
(X는 회색 계열, –는 더 흐리게). 이 화면에서 제일 중요한 규칙이다 - 계산이 안 된 것을
탈락으로 읽으면 판단이 통째로 틀어진다.

## 4. API

### 4-1. `GET /api/quarterly?market=KR`

최신 분기를 API가 정한다: `SELECT MAX(fiscal_year*10 + fiscal_quarter)` 방식이 아니라
`ORDER BY fiscal_year DESC, fiscal_quarter DESC LIMIT 1`로 찾는다(연·분기 따로 정렬해야
2025Q4 > 2026Q1로 뒤집히지 않는다).

```json
{
  "fiscal_year": 2026,
  "fiscal_quarter": 3,
  "market_reference": { "median_revenue_growth": 0.16, "sample_size": 607 },
  "themes": [
    {
      "theme_id": "ai_semiconductor",
      "classification": "조용한 변화",
      "financial_on": true,
      "financial_changed": 7,
      "financial_judged": 8,
      "financial_ratio": 0.875,
      "news_high": false,
      "news_ratio": 1.0,
      "news_this_quarter": 3851,
      "previous_classification": null
    }
  ]
}
```

- 읽는 표: `quarterly_theme_classification`, `quarterly_market_reference`.
- `previous_classification`은 `src/db/quarterly_classification.py`의
  `previous_classification()`과 같은 규칙(직전 분기, 연도 경계 넘김)으로 채운다.
  기록이 없으면 `null`.
- 분기 행이 하나도 없으면 `{"fiscal_year": null, "themes": []}`로 내려준다(주간 API가
  `week_start: null`로 처리하는 것과 같은 관례).

### 4-2. `GET /api/quarterly/members?theme_id=...&market=KR`

```json
{
  "fiscal_year": 2026, "fiscal_quarter": 3,
  "members": [
    {
      "ticker": "005930",
      "revenue_transition": true, "revenue_flow": true, "profit_transition": true,
      "changed": true,
      "revenue_recent": 171499500000000, "revenue_year_ago": 74566300000000,
      "psr": 3.39, "per": 10.9, "valuation_tier": "중간",
      "finance": { "status": "pass", "piotroski": 7, "reasons": [] }
    }
  ]
}
```

- 읽는 표: `quarterly_company_signals` (분기는 4-1과 같은 방식으로 최신 분기).
- `finance`는 **기존 `/api/radar/members`의 코드를 그대로 옮긴다**(SPEC 5-3: 기존 로직 그대로,
  새로 계산하지 않는다). 출처는 `watchlist_screening_results`
  (`symbol`, `status`, `piotroski`, `red_flags`) - 그 라우트처럼 `try/catch`로 감싸서
  **표가 없거나 조회가 실패해도 기업 목록 자체는 나오게** 한다.
- 정렬은 API가 하지 않는다(화면이 3-3 규칙으로 한다). 티커순으로 내려주면 된다.

> **의존성 주의.** `watchlist_screening_results`는 **주간 파이프라인**(weekly-watchlist)이
> 채운다. SPEC 10장대로 주간 Actions를 끄면 이 표가 그대로 멈춰서, 분기 화면의 재무 배지만
> 조용히 낡은 값이 된다. 전환할 때 (a) 트랩 필터 계산을 분기 파이프라인으로 옮기거나
> (b) 주간 중 이것만 남기거나 둘 중 하나를 정해야 한다. **이 화면을 만들면서 정할 일은
> 아니고, 10장 전환 때 반드시 꺼낼 항목이다.**

### 4-3. 공통

- 기존 `/api/radar/*` 라우트와 같은 모양: `getClient()` 직접 사용, `export const dynamic = "force-dynamic"`,
  실패 시 빈 결과 + `console.error`(화면이 죽지 않게).
- **Turso는 INTEGER를 문자열로 돌려준다.** `financial_changed` 같은 값을 그대로 JSON에
  실으면 화면에서 `"7"`이 된다. 라우트에서 `Number()`로 바꿔 내려준다 - 이 저장소가
  파이썬 쪽에서 `_coerce()`로 겪은 것과 같은 함정이다.
- `financial_on` / `news_high` / `changed`는 1/0/NULL로 저장돼 있다. `true`/`false`/`null`로
  바꿔 내려준다. **0과 null을 절대 같이 뭉개지 않는다.**
