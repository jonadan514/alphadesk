# AlphaDesk 리서치 레이더 — 분기 재설계 명세 (2026-09)

> 이 문서는 `redesign-quarterly` 브랜치 작업의 기준이다.
> 작업 전 반드시 끝까지 읽고, 이 문서와 기존 코드가 충돌하면 **이 문서를 따른다.**
> 사용자는 비개발자다. 각 단계가 끝나면 무엇을 했는지 쉬운 말로 요약하고, 다음 단계로 넘어가기 전에 확인을 받는다.

---

## 1. 목적

**구조적 변화가 시작된 기업이 몰린 산업 테마와, 그 안의 기업 후보를 찾는다.**

- 용도: 워치리스트 후보 발굴. 매수·매도 판단 도구가 아니다.
- 투자 기간: 약 3년. 단기 모멘텀은 보지 않는다.
- 이 툴이 모든 판단을 하지 않는다. 후보를 좁히는 데까지만 한다.

## 2. 무엇이 바뀌나

| 구분 | 기존 | 새 설계 |
|---|---|---|
| 실행 주기 | 매주 일요일 밤 | **분기 1회** (실적 발표 후) |
| 테마 판단 | 뉴스·실적·주가 3축 + 라벨 6종 | **재무 신호 × 뉴스 언급 → 4칸 분류** |
| 기업 정보 | 없음 (테마 단위에서 멈춤) | **기업 카드** (변화 신호 3개 + 트랩 필터 + 밸류 위치) |
| 재무 데이터 | 매출 성장률 스냅샷 | **최근 5분기** 매출·영업이익 |
| 한국 재무 출처 | yfinance | **DART 재무 API** |

### 그대로 유지
- 테마 매핑 파이프라인 전체 (경로 A/B, 코드 검증, 비판 패스, 근거 감사, 판정 원장, 사람 검토, 확정 소속 기본 복원)
- 트랩 필터와 기준값 (F-Score 6, ROE 미국 12% / 한국 8%, 이자보상 3배, 부채비율 150%)
- 유니버스 (미국 S&P500, 한국 시총 3000억 이상)
- 뉴스 수집 코드 (점검 후 보완, 6장 참고)

### 끄기 (삭제 금지)
- 주간 GitHub Actions 일정: 일정만 비활성화
- 주가 축(4주 상대수익률), 라벨 6종 코드: 새 설계가 안정될 때까지 남겨둔다
- 텔레그램 주간 요약: 비활성화

### 하지 않음
- 수출통계, 수주 금액·수주잔고, 애널리스트 리비전, 가설 기록

## 3. 지켜야 할 원칙 (기존과 동일)

1. 종합 점수·등급을 만들지 않는다. 신호는 각각 표시한다.
2. LLM은 숫자를 만들지 않는다. 모든 수치는 코드가 원본 데이터로 계산한다.
3. 트랩 필터 기준값은 고정한다.
4. 판정은 **통과 / 탈락 / 데이터부족** 3분류. 계산할 수 없으면 탈락이 아니라 데이터부족이다.
5. 이력 테이블은 덮어쓰지 않는다. 새 분기 결과는 새 행으로 쌓는다.

## 4. 데이터

### 4-1. 한국: DART OpenAPI
- API 키는 환경변수 `DART_API_KEY`로 받는다. 코드·저장소에 키를 적지 않는다. GitHub Actions에서는 Secrets로 넣는다.
- **기업개황**: 사업정보가 없는 코스닥 84종목의 사업 설명 보강에 사용 (매핑 프롬프트에 첨부).
- **분기 재무**: 매출액, 영업이익. 최근 5분기.
- 주의할 점
  - **연결재무 우선, 없으면 별도재무.** 어느 쪽을 썼는지 기록한다.
  - **4분기 값은 직접 계산해야 한다.** 사업보고서는 연간 합계라서 `4분기 = 연간 − (1~3분기 누적)`.
  - 반기·3분기 보고서의 손익은 "해당 3개월"과 "누적" 값이 함께 있다. **3개월 값**을 쓴다.
  - 기업코드(corp_code)와 종목코드 매핑 파일을 캐시해 둔다.
  - 호출 한도가 있으므로 재시도(기존 429 재시도 방식 참고)와 캐시를 적용한다.

### 4-2. 미국: yfinance
- 분기 손익계산서에서 매출(Total Revenue), 영업이익(Operating Income) 최근 5분기.
- yfinance가 주는 분기 수가 종목마다 다르다. 5분기가 안 되면 해당 신호는 데이터부족.

### 4-3. 밸류용 가격 데이터
- 시가총액: yfinance 현재값.
- PSR, PER은 yfinance 값을 그대로 쓰지 않고 **직접 계산**한다 (한국 값이 비어 있는 경우가 많고, 기준을 통일하기 위해).
  - PSR = 시가총액 ÷ 최근 4분기 매출 합
  - PER = 시가총액 ÷ 최근 4분기 순이익 합 (순이익 합이 0 이하이면 PER 표시 안 함)
  - 한국 순이익도 DART에서 함께 수집한다.

### 4-4. 저장
- 분기 재무는 `기업 × 분기` 단위로 원본값을 저장 (계산값과 분리).
- 각 행에 출처(DART/yfinance), 연결/별도 구분, 수집일을 남긴다.

## 5. 기업 카드

### 5-1. 변화 신호 3개

"최근 분기"는 수집 시점에 공시된 가장 최근 분기다. "1년 전 같은 분기"는 그보다 4분기 앞이다.

| 신호 | 통과 조건 | 데이터부족 |
|---|---|---|
| 매출 전환 | 최근 분기 매출 ≥ 1년 전 같은 분기 매출 × 1.20 | 두 분기 중 하나라도 값 없음, 또는 1년 전 매출 ≤ 0 |
| 매출 흐름 | 5분기 중 직전 분기 대비 매출 증가가 **4번 중 3번 이상** | 5분기 값이 다 없음 |
| 이익 전환 | 영업이익률이 1년 전 같은 분기보다 높음, **또는** 1년 전 영업이익 < 0 이고 최근 영업이익 > 0 | 두 분기 중 하나라도 매출 또는 영업이익 없음 |

- 기준값(20%, 3/4)은 설정 파일에 둔다. 코드에 직접 박지 않는다.
- 화면 참고값: **국가별 유니버스 전체의 매출 증가율(1년 전 같은 분기 대비) 중앙값**을 함께 표시한다. 판정에는 쓰지 않는다.

### 5-2. 변화 기업 판정
- 매출 전환 **통과**, 그리고
- 매출 흐름 또는 이익 전환 중 **하나 이상 통과**
- 매출 전환이 데이터부족이면 → 변화 기업 판정도 데이터부족

### 5-3. 트랩 필터
- 기존 로직 그대로 옆에 표시. 변화 기업 판정에는 섞지 않는다.

### 5-4. 밸류 위치
- **같은 테마 안에서** PSR을 3등분해 `싼 편 / 중간 / 비싼 편`으로 표시.
- 흑자 기업은 PER 값도 함께 표시 (등분 없이 수치만).
- 테마 안에서 PSR 값이 있는 기업이 3곳 미만이면 데이터부족.
- 판정 신호가 아니라 참고 표시다.

### 5-5. 기저효과 (지금은 구현하지 않음)
- 매출이 아주 작은 기업이 쉽게 +20%를 넘는 문제가 있을 수 있다.
- 첫 분기 결과를 보고 필요하면 "분기 매출 최소 금액" 조건을 추가한다.

## 6. 뉴스 언급

### 6-1. 먼저 할 일: 기존 수집 코드 점검 (수정 금지)
아래 5가지를 정리해 사용자에게 보고한다.
1. 출처 API
2. 테마별 기사 매칭 방식 (키워드 목록 포함)
3. 중복 기사 제거 여부
4. 기사 보관 기간 (과거 1년치가 있는지)
5. 분기를 나누는 날짜 기준 (수집일인지 발행일인지)

### 6-2. 목표 기준 (점검 결과를 보고 사용자와 확정)
- **발행일 기준**으로 분기를 나눈다.
- **중복 제거**: 제목이 거의 같은 기사는 하나로 센다.
- **시황 기사 제외**: 제목에 주가 관련 단어(예: 급등, 급락, 주가, 특징주, 상한가, 하한가)가 있으면 제외. 단어 목록은 설정 파일로 관리.
- 단위는 **테마**. 기업 단위 뉴스는 이번 범위에서 제외 (그룹명·동음이의어 문제).

### 6-3. 뉴스 비율
- 뉴스 비율 = 이번 분기 기사 수 ÷ 직전 4분기 평균 기사 수
- 직전 4분기 이력이 다 없으면 **데이터부족** (있는 분기만으로 평균 내지 않는다).

## 7. 테마 4칸 분류

### 7-1. 재무 신호 "켜짐"
- 소속 기업 중 변화 기업 비율 **30% 이상**, 그리고 변화 기업 **2곳 이상**
- 비율의 분모는 변화 기업 판정이 데이터부족이 아닌 기업 수
- 분모가 2 미만이면 데이터부족

### 7-2. 뉴스 "많음"
- 뉴스 비율 **1.5 이상**

### 7-3. 분류

| 재무 신호 | 뉴스 | 분류 | 의미 |
|---|---|---|---|
| 켜짐 | 적음 | **조용한 변화** | 가장 먼저 볼 후보 |
| 켜짐 | 많음 | **확인된 변화** | 밸류 위치를 꼭 확인 |
| 꺼짐 | 많음 | **기대 선행** | 다음 분기 재무가 따라오는지 관찰 |
| 꺼짐 | 적음 | **관심 밖** | — |

- 둘 중 하나라도 데이터부족이면 분류하지 않는다.
- 기준값(30%, 2곳, 1.5배)은 설정 파일에 둔다.
- 분기별 분류 결과를 이력으로 쌓는다 (지난 분기 대비 바뀐 테마를 볼 수 있게).

## 8. 화면

- **테마 목록**: 4칸 분류, 변화 기업 수 / 판정 가능 기업 수, 뉴스 비율, 지난 분기 분류. 분류별 필터.
- **테마 상세**: 소속 기업 카드 목록. 점수 없이 정렬·필터만 제공.
  - 필터 예: 변화 기업만 / 트랩 필터 통과만 / 밸류 싼 편만
- 모든 화면에 데이터 기준 분기와 시장 매출 증가율 중앙값을 표시.

## 9. 실행

- 분기 1회 GitHub Actions. 순서: DART·yfinance 재무 수집 → 변화 신호 계산 → 밸류 계산 → 뉴스 분기 집계 → 4칸 분류 → 화면 데이터 갱신.
- 매핑 파이프라인(분기)은 기존대로. 재무 계산은 **승인된 매핑**만 사용.
- 수동 실행도 가능하게 한다 (workflow_dispatch).

## 10. 작업 순서

각 단계 끝에 결과를 요약하고 사용자 확인을 받는다.

1. `redesign-quarterly` 브랜치 생성, 이 문서를 `docs/`에 저장
2. 뉴스 수집 코드 점검 보고 (6-1, 코드 수정 없음)
3. DART 연동: 기업코드 매핑, 기업개황(코스닥 84종목 사업정보), 분기 재무 수집
   - 확인: 삼성전자·에코프로 등 몇 종목의 5분기 매출·영업이익을 표로 보여주기
4. 미국 yfinance 5분기 재무 수집, 종목별 확보 분기 수 통계 보고
5. 변화 신호 3개 + 변화 기업 판정 계산
   - 확인: 국가별 통과/탈락/데이터부족 건수, 시장 중앙값
6. 밸류 위치 계산
7. 뉴스 기준 보완 (6-2, 사용자 확정 후) + 분기 집계
8. 테마 4칸 분류
9. 화면 반영
10. 주간 Actions 비활성화, 분기 Actions 추가

## 11. 첫 분기 후 다시 볼 것

- 기준값 조정: 매출 전환 20%, 변화 기업 30%·2곳, 뉴스 1.5배
- 기저효과로 이상한 기업이 많이 걸리는지
- 시황 기사 제외 단어 목록이 적절한지
- 실행 편차 2층 구조(B안) 결과 (10월 1일 분기 실행)
- 매핑 모델 교체(A안) 여부
